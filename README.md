# networkAppServer

Серверная часть сетевого приложения для обмена сообщениями и файлами в реальном времени. Проект реализует WebSocket-сервер на Node.js с шифрованием трафика (алгоритм «Магма»), аутентификацией по электронной подписи, хранением истории сообщений в SQLite и загрузкой файлов в S3-совместимое хранилище (например, RustFS).

Клиент — Qt/C++ приложение; структуры пакетов протокола описаны в заголовочном файле клиента (`User`, `ChatMessage`, `MarkAsRead`, `SentMessageId`, `ChatList`, `GetChat`, `ServerHandshake`, `FileChunkPacket`, `FileDownloadRequest`, `CallSignalPacket`, `IceCandidatePacket`).

## Возможности

- **WebSocket-соединение** для мгновенной доставки сообщений.
- **Шифрование полезной нагрузки** симметричным алгоритмом «Магма» после установки сессионного ключа.
- **Аутентификация клиента** через проверку электронной подписи (рукопожатие).
- **Хранение истории переписки** в базе данных SQLite.
- **Обмен файлами** чанками с последующей загрузкой в S3-совместимое объектное хранилище.
- **Управление списком пользователей** в сети (онлайн-статус, широковещательная рассылка).
- **Отметка сообщений как прочитанных**.
- **Сигнализация для аудио/видеозвонков** (SDP и ICE-кандидаты).

## Технологии

- **Node.js** (ES-модули)
- **WebSocket** (`ws`)
- **SQLite** (`sqlite`, `sqlite3`)
- **Криптография**: встроенный модуль `crypto` + реализация алгоритма «Магма» (`magma.js`)
- **AWS SDK for JavaScript v3** (`@aws-sdk/client-s3`) для работы с S3-совместимым хранилищем
- **dotenv** для управления переменными окружения

## Требования

- Node.js версии 18 или выше (рекомендуется LTS).
- Доступ к S3-совместимому хранилищу (например, [RustFS](https://github.com/rustfs/rustfs)) с учётными данными.
- Свободный порт `5000` (порт WebSocket-сервера можно изменить в коде).

## Установка

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/Leonid-Gorelov/networkAppServer.git
   cd networkAppServer
   ```

2. Установите зависимости:
   ```bash
   npm install
   ```

3. Создайте файл `.env` в корне проекта и заполните параметры подключения к S3:
   ```env
   S3_ENDPOINT=http://localhost:9000
   S3_REGION=us-east-1
   S3_ACCESS_KEY_ID=ваш_access_key
   S3_SECRET_ACCESS_KEY=ваш_secret_key
   S3_BUCKET_NAME=uploads
   ```
   > Если вы используете RustFS, значения `S3_ENDPOINT` и `S3_REGION` могут отличаться. Уточните их в документации вашего хранилища.

4. (Опционально) Сгенерируйте пару ключей сервера для рукопожатия. В `server.js` есть функция `generateServerKeyPair()`, которая создаёт файлы `server_private.pem` и `server_public.pem`. Раскомментируйте её вызов при первом запуске:
   ```javascript
   // В server.js раскомментируйте строку:
   // generateServerKeyPair();
   ```
   После генерации скопируйте `server_public.pem` в клиентское приложение.

## Запуск

```bash
node server.js
```

Сервер запустится и будет слушать WebSocket-подключения на порту `5000`. При старте также инициализируются база данных SQLite и S3-клиент.

## Протокол WebSocket

Обмен данными идёт в формате JSON. Каждый пакет содержит поле `type`. После установки сессионного ключа полезная нагрузка шифруется и передаётся в зашифрованном виде (в клиенте — через «Магму»).

### Типы пакетов

Ниже — типы из клиентских определений. Для каждого указаны поля и направление (направление выведено из назначения структуры и подлежит сверке с серверным кодом).

#### `user` — клиент → сервер

Регистрация/вход пользователя с публичным ключом и подписью.

| Поле | Тип | Описание |
|------|-----|----------|
| `Name` | string | Имя пользователя |
| `ClientPublicKey` | string | Публичный ключ клиента |
| `Signature` | string | Электронная подпись |
| `type` | string | `"user"` |

#### `serverHandshake` — сервер → клиент

Ответ сервера на вход: публичный ключ сервера и подпись.

| Поле | Тип | Описание |
|------|-----|----------|
| `ServerPublicKey` | string | Публичный ключ сервера |
| `Signature` | string | Подпись сервера |
| `type` | string | `"serverHandshake"` |

#### `chatMessage` — оба направления

Текстовое сообщение (отправка клиентом, доставка получателю, история из БД).

| Поле | Тип | Описание |
|------|-----|----------|
| `Name` | string | Отправитель |
| `Message` | string | Текст сообщения |
| `Target` | string | Получатель |
| `GotFromDB` | bool | Признак сообщения из истории |
| `Date` | string | Дата/время |
| `Id` | int | Идентификатор в БД |
| `TempId` | int | Временный ID (для сопоставления с `sentMessageId`) |
| `IsRead` | bool | Прочитано ли |
| `FilePath` | string | Путь к вложению (если есть) |
| `FileType` | string | Тип вложения |
| `FileName` | string | Имя вложения |
| `type` | string | `"chatMessage"` |

#### `sentMessageId` — сервер → клиент

Подтверждение сохранения сообщения: сопоставление временного и постоянного ID.

| Поле | Тип | Описание |
|------|-----|----------|
| `TempId` | int | Временный ID, отправленный клиентом |
| `Id` | int | Постоянный ID в БД |
| `IsRead` | bool | Статус прочтения |
| `type` | string | `"sentMessageId"` |

#### `markAsRead` — клиент → сервер

Отметка сообщений как прочитанных.

| Поле | Тип | Описание |
|------|-----|----------|
| `Id` | int | ID сообщения |
| `type` | string | `"markAsRead"` |

#### `getChat` — клиент → сервер

Запрос истории переписки с пользователем.

| Поле | Тип | Описание |
|------|-----|----------|
| `Name` | string | Имя собеседника |
| `type` | string | `"getChat"` |

#### `chatsList` — сервер → клиент

Список чатов/пользователей.

| Поле | Тип | Описание |
|------|-----|----------|
| `Names` | string[] | Имена собеседников/пользователей |
| `type` | string | `"chatsList"` |

#### `fileChunk` — клиент → сервер

Часть файла с метаданными.

| Поле | Тип | Описание |
|------|-----|----------|
| `FileId` | string | Уникальный ID файла |
| `FileName` | string | Имя файла |
| `ChunkIndex` | int | Номер чанка |
| `TotalChunks` | int | Всего чанков |
| `Base64Data` | string | Данные чанка (Base64) |
| `Target` | string | Получатель |
| `Sender` | string | Отправитель |
| `TempId` | int | Временный ID сообщения |
| `type` | string | `"fileChunk"` |

#### `fileDownloadRequest` — клиент → сервер

Запрос на скачивание файла.

| Поле | Тип | Описание |
|------|-----|----------|
| `FilePath` | string | Путь к файлу в хранилище |
| `Sender` | string | Кто запрашивает |
| `type` | string | `"fileDownloadRequest"` |

#### Сигнализация звонков — оба направления

`type` в `CallSignalPacket` задаётся динамически (SDP offer/answer, служебные сигналы).

| Поле | Тип | Описание |
|------|-----|----------|
| `type` | string | Тип сигнала |
| `Target` | string | Получатель |
| `Sender` | string | Отправитель |
| `Sdp` | string | SDP-описание |

#### `iceCandidate` — оба направления

ICE-кандидат для установки соединения.

| Поле | Тип | Описание |
|------|-----|----------|
| `Target` | string | Получатель |
| `Sender` | string | Отправитель |
| `Candidate` | string | ICE-кандидат |
| `Mid` | string | Media ID |
| `type` | string | `"iceCandidate"` |

### Пример пакета (после установки ключа)

```json
{
  "type": "chatMessage",
  "encryptedData": "base64-строка-с-зашифрованным-содержимым"
}
```

> Формат «конверта» с шифрованием (`encryptedData` или иное поле) уточняется по реализации в `wsController.js` / `magma.js`.

## Безопасность

- **Шифрование**: после рукопожатия данные передаются в зашифрованном виде с использованием алгоритма «Магма» и сессионного ключа.
- **Аутентификация**: клиент подтверждает личность электронной подписью (`User.Signature`), сервер — своей (`ServerHandshake.Signature`).
- **Ключи сервера**: приватный ключ (`server_private.pem`) хранится только на сервере; публичный (`server_public.pem`) распространяется вместе с клиентом.
